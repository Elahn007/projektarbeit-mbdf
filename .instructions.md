# Agent Instructions - Münchenbernsdorf Website v2.0

## Purpose
These instructions guide developers and AI agents when working on this project. They document best practices, architectural decisions, and common patterns to maintain consistency.

## Project Context
- **Name:** Münchenbernsdorf Discovery Website
- **Target Users:** Elementary school children (6-12 years) & teachers
- **Tech Stack:** Vanilla HTML5/CSS3/JavaScript (no frameworks)
- **Architecture:** PWA with Service Worker, localStorage state management
- **Current Version:** 2.0.0 (enhanced with accessibility, gamification, analytics)

---

## Core Principles

### 1. Progressive Enhancement
- Core content works without JavaScript
- CSS provides visual enhancements
- JavaScript adds interactivity & features
- Graceful degradation for older browsers

### 2. Accessibility First
- WCAG 2.1 AA/AAA compliance target
- Semantic HTML structure
- ARIA labels on interactive elements
- Keyboard navigation throughout
- High contrast support (`body.high-contrast`)
- Font size adjustment support (`html.font-size-*`)

### 3. Performance Matters
- Critical CSS inlined in `<head>` for fast FCP
- Async stylesheet loading with preload
- Images lazy-loaded with responsive srcset
- Service Worker caching strategy
- Minimal bundle size (no frameworks)

### 4. Mobile-First Responsive Design
- CSS `clamp()` for fluid scaling
- Touch-friendly buttons (44×44px minimum)
- PWA app-like experience on mobile
- Hamburger menu for small screens

### 5. Privacy & Security
- No third-party trackers (Plausible optional)
- localStorage for preferences (no cookies)
- Input sanitization for forms
- CSP headers in web.config
- Honeypot spam protection

## JavaScript Architecture

### Storage Keys (localStorage)
Always use the `STORAGE` object defined at top of script.js:

```javascript
const STORAGE = {
    theme: "darkMode",
    visited: "visitedPlaces",
    analytics: "mb_analytics_v1",
    visitorFilter: "mb_visitor_filter",
    achievements: "mb_achievements_v1",
    quizDifficulty: "mb_quiz_difficulty",
    fontSize: "mb_font_size",
    highContrast: "mb_high_contrast"
};
```

### Initialization Order
The `init()` function (line ~1300) orchestrates startup:
1. Apply theme from localStorage
2. Restore visited places
3. Setup DOM listeners & navigation
4. Setup interactions (search, filtering)
5. Setup accessibility controls
6. Setup offline UI
7. Setup PWA shortcuts
8. Inject dynamic components (quiz, tour, feedback)
9. Track page view

**Key:** Always add new setup functions to `init()` with descriptive names.

### Component Registration Pattern
Components use consistent setup function pattern:

```javascript
function setupComponentName() {
    // 1. Get/create DOM elements
    const container = document.getElementById('component-id');
    if (!container) return; // Skip if not present
    
    // 2. Initialize state
    const state = {
        data: [],
        isActive: false
    };
    
    // 3. Add event listeners
    container.addEventListener('click', handleClick);
    
    // 4. Populate initial content
    render();
}

function render() {
    // Update DOM based on state
}
```

## CSS Architecture

### Design System
All colors are CSS variables in `:root`:

```css
:root {
    /* Brand */
    --accent: #2563eb;           /* Primary blue */
    --accent-strong: #1d4ed8;    /* Darker blue */
    --accent-alt: #0891b2;       /* Cyan accent */
    
    /* Status */
    --success: #10b981;
    --warning: #f59e0b;
    --danger: #ef4444;
    
    /* Text & Background */
    --bg: #f3f6fb;              /* Light background */
    --text: #10213a;            /* Dark text */
    --muted: #465b7a;           /* Muted color */
    --line: rgba(16,33,58,0.12); /* Borders */
    
    /* Sizing */
    --radius-xl: 24px;
    --radius-lg: 18px;
    
    /* Shadows */
    --shadow-sm: 0 8px 24px rgba(16,33,58,0.08);
    --shadow-md: 0 18px 40px rgba(16,33,58,0.14);
    --shadow-lg: 0 24px 52px rgba(16,33,58,0.2);
}

body.dark {
    --bg: #0b1322;
    --text: #e8eef9;
    --accent: #60a5fa;
    /* Override other vars */
}
```

### Adding New Features - CSS Checklist
When adding new JS features, add corresponding CSS:
- [ ] Component styling (`.component-name`)
- [ ] Hover/active states (`:hover`, `:active`, `.active`)
- [ ] Dark mode support (`body.dark .component-name`)
- [ ] Mobile responsive (media queries)
- [ ] Animation/transition (if interactive)
- [ ] Accessibility focus (`focus-visible`, outline)
- [ ] High contrast support (`body.high-contrast`)

### Animation Pattern
Use consistent timing function and durations:

```css
/* Springy, modern feel */
transition: all 0.2s cubic-bezier(0.34, 1.56, 0.64, 1);

/* Named animations */
@keyframes slideUp {
    from { opacity: 0; transform: translateY(20px); }
    to { opacity: 1; transform: translateY(0); }
}
```

## Common Tasks

### Adding a New Detail Page
1. **Create HTML file:** Copy structure from `kirche.html`
2. **Update style.css:** Add `.page-id` specific styles if needed
3. **Update data/content.de.json:** Add place data object
4. **Update index.html:** Add card linking to new page
5. **Update manifest.json:** Add shortcut if high priority
6. **Test:** Verify all links work, CSS loads, JavaScript initializes

### Adding a New Feature
1. **Plan state:** Identify localStorage keys needed
2. **Create setup function:** Add to script.js
3. **Add DOM structure:** Create elements in HTML or inject via JS
4. **Add CSS styling:** Add to style.css (include dark mode, mobile, a11y)
5. **Wire event listeners:** Connect interaction to functionality
6. **Update init():** Call your setup function
7. **Test:** Manual browser testing + check console for errors

### Modifying Colors/Theme
1. Change CSS variable in `:root`
2. Consider dark mode variant
3. Test high contrast: apply `body.high-contrast` class
4. Test with different font sizes (`html.font-size-*`)

### Adding Analytics Events
1. Import tracking function: `trackEventEnhanced(name, props)`
2. Call with event name and optional properties:
   ```javascript
   trackEventEnhanced('feature_used', { feature: 'xyz', value: 123 });
   ```
3. Both local storage and Plausible analytics will track
4. Check manifest Plausible dashboard for data

## Best Practices

### Naming Conventions
- **CSS Classes:** kebab-case (`.card-content`, `.quiz-section`)
- **IDs:** kebab-case for structure (`#quiz`, `#main-content`)
- **JavaScript functions:** camelCase (`setupQuiz()`, `loadAchievements()`)
- **JavaScript variables:** camelCase with descriptive names

### Error Handling
Always gracefully handle missing elements:

```javascript
const element = document.getElementById('optional-component');
if (!element) return; // Skip setup if not present

try {
    // Your code
} catch (e) {
    console.error('Component initialization failed:', e);
}
```

### Responsive Images
Always include responsive variants:

```html
<picture>
    <source srcset="image-480w.webp 480w, image-768w.webp 768w" 
            type="image/webp">
    <img src="image.jpg" 
         srcset="image-480w.jpg 480w, image-768w.jpg 768w" 
         sizes="(max-width: 600px) 100vw, (max-width: 1200px) 80vw, 1000px"
         loading="lazy" 
         decoding="async" 
         alt="Descriptive alt text">
</picture>
```

### Accessibility Must-Haves
- [ ] Semantic HTML: `<nav>`, `<main>`, `<section>`, `<article>`
- [ ] Alt text on all images
- [ ] ARIA labels on buttons without text
- [ ] Keyboard navigation (Tab, Enter, Arrow keys)
- [ ] Focus indicators (3px outline)
- [ ] Skip to main content link (`.skip-link`)
- [ ] Screen reader text for icons (`.sr-only`)

## Getting Help

### Debugging Tips
1. Open DevTools (F12)
2. Check Console for errors
3. Inspect Elements in Inspector
4. Verify CSS in Computed Styles
5. Check localStorage in Application tab

### Common Issues

**CSS not loading?**
- Check async preload in HTML head
- Verify style.css path is correct
- Check browser cache (Ctrl+Shift+Delete)

**JavaScript not working?**
- Check for console errors
- Verify DOM element IDs match
- Check if init() ran
- Test with console: `window.features`

**Service Worker not updating?**
- Update CACHE_NAME in service-worker.js
- Use Ctrl+Shift+Delete to clear cache
- Check Application → Service Workers tab
